BillHub UI 设计规范

本地优先的个人记账应用界面设计方案

版本 2.0 · 2026年9月 · 适配 Tauri 桌面端 (1180×780)

绿色 = 收入 红色 = 支出 暖色纸感主题

1设计哲学

围绕中国用户记账习惯，建立"清晰、温暖、可控"三大设计原则

清

清晰 Clarity

信息层级一目了然。用户打开应用即可看到财务全貌：本月收入、支出、结余，无需翻找。关键数字使用大字号 + 等宽数字字体（tabular-nums），金额对齐便于扫读。

暖

温暖 Warmth

暖色纸感背景（#f7f3ec）建立信任感与亲和力，区别于冷冰冰的金融工具。深绿色侧边栏营造稳重氛围，搭配圆润的圆角（12-18px）和柔和阴影，让记账变得轻松愉悦。

控

可控 Control

数据操作可追溯。导入前预览、批次可撤销、流水可编辑可批量修改。所有破坏性操作需二次确认，让用户始终感到对财务数据拥有完全控制权。本地优先，隐私无忧。

核心洞察：中国用户记账的核心习惯是"先看总览，再查细节"。因此新增「仪表盘」作为默认首页，打开即见月度财务概况、支出分类和消费日历，符合"打开→扫一眼→放心"的心理路径。

6页面详细设计

四个核心页面的设计规格与交互说明

6.1 仪表盘（新增 · 默认首页）

设计目标：用户打开应用第一眼即可掌握财务全貌，无需主动操作。

  • 月度概览卡片区（顶部）：两张大卡片展示「本月收入」和「本月支出」，含环比趋势箭头；下方三张小卡片展示「结余」「交易笔数」「待处理」
  • 支出分类环形图（左下）：本月支出按分类占比的环形图，中心显示总额，下方图例标注各分类百分比
  • 消费日历热力图（右下）：按日历展示每日支出强度，颜色从浅到深表示消费金额，直观呈现消费节奏
  • 最近流水预览（底部）：展示最新 3-5 条流水摘要，点击「查看全部」跳转流水明细页
  • 月份选择器（右上角）：下拉切换查看月份，默认当前月
用户习惯对应："这个月花了多少？""钱花在哪了？""哪天花得最多？" —— 仪表盘一次性回答这三个核心问题。

6.2 导入中心（优化交互）

设计目标：让导入流程更顺滑，降低操作焦虑。

  • 拖拽上传区（左列）：支持拖拽文件到上传区，也支持点击选择。显示支持的文件格式提示
  • 智能预览卡片（中列）：选择文件后自动识别平台，展示记录数、可入账数、错误行、时间范围和 SHA256 指纹
  • 替换选项：勾选「替换同指纹批次」可覆盖重复导入，默认关闭
  • 批次管理列表（右列）：展示所有导入批次，每个批次显示平台、时间、条数和 SHA256 前12位，支持撤销
  • 问题行展示：错误行和警告分行展示，错误用红色背景、警告用琥珀色背景
交互优化：导入成功后自动跳转到流水明细页，让用户立即看到导入结果，形成操作闭环。

6.3 流水明细（增强视觉层次）

设计目标：让大量流水的浏览、筛选和管理更高效。

  • 标签式筛选器（替代下拉框）：平台筛选改为标签按钮组（全部 / 微信 / 支付宝），一键切换，当前选中绿色填充。分类和状态保留下拉框
  • 来源色彩标签：每行流水用小标签标注来源（微信=浅绿底绿字，支付宝=浅蓝底深蓝字），快速区分
  • 双行信息展示：对方/说明列采用双行布局，主标题加粗（对方名称），副标题灰色（描述 · 账户）
  • 金额右对齐 + 符号：支出红色加负号，收入绿色加正号，中性黑色无符号，等宽数字保证对齐
  • 浮动批量操作栏：选中任意行后，顶部出现蓝色批量操作栏，显示已选数量和操作按钮（改类型 / 改状态 / 批量保存 / 取消）
  • 行内编辑：点击编辑按钮，当前行变为编辑模式，下拉选择类型和状态，保存或取消
  • 分页控件：右下角分页，支持切换每页条数（20/50/100），显示当前页码和总页数

6.4 收支分析（扩展可视化）

设计目标：从多维度呈现收支规律，辅助财务决策。

  • 月度/年度切换：分段控件切换分析粒度
  • 累计统计卡片：四张卡片展示累计收入、累计实际支出、累计结余、周期数/笔数
  • 收支趋势折线图：双线图展示收入和支出趋势，带面积填充和悬停 tooltip，点击数据点可下钻查看该周期流水
  • 周期明细表：表格展示每个周期的收入、支出、净额和笔数，点击可跳转流水明细
  • 最新周期摘要：高亮展示最新周期的收入和支出数据
新增建议：可增加「分类占比分析」模块，按消费类别展示支出分布柱状图，让用户了解"钱花在了哪里"。此功能依赖后端增加分类聚合 API。

空状态设计

所有列表/图表在无数据时展示友好的空状态提示，而非空白区域：

  • 仪表盘无数据：中央显示"请先导入账单，开始你的记账之旅" + 导入按钮
  • 流水列表无数据：表格区域显示"暂无流水"或"正在加载..."
  • 趋势图无数据：图表区域显示"暂无可展示的趋势数据"
  • 分析表无数据：表格显示"暂无可分析的收支记录，请先导入账单"

加载状态

  • 按钮操作：按钮文字变为"解析中..."/"保存中..."并禁用
  • 表格加载：aria-busy="true" + 显示"正在加载流水..."
  • 图表加载：显示"数据加载中..."占位

8无障碍设计

确保所有用户都能顺畅使用

  • 语义化 HTML：使用 <nav>、<main>、<section>、<table> 等语义标签
  • ARIA 标注：所有可交互元素添加 aria-label，图表添加 role="group" 和描述
  • 键盘导航：所有按钮和链接可通过 Tab 键访问，Enter/Space 触发操作
  • 焦点指示：聚焦时显示 2px 绿色 outline，偏移 3px
  • 对比度：所有文字与背景对比度 ≥ 4.5:1（WCAG AA 标准）
  • 表格滚动：宽表格横向滚动，表头固定，不丢失上下文

9实施建议

设计方案的技术落地路径

分阶段实施

阶段内容工作量评估
Phase 1新增仪表盘页面 + 月份选择器 + 概览卡片需后端新增月度统计 API
Phase 2流水页面筛选器改造（标签化）+ 来源色彩标签纯前端改造
Phase 3仪表盘支出分类环形图 + 消费日历热力图需后端新增分类聚合 API
Phase 4分析页面扩展（分类占比分析）需后端新增分类统计 API
Phase 5交互细节打磨（空状态、加载态、动画过渡）纯前端优化

技术栈兼容

  • 现有技术栈完全兼容：React 19 + TypeScript + Vite + 原生 CSS
  • 无需引入 UI 框架，保持轻量。环形图和热力图可用 SVG 手绘（与现有趋势图一致）
  • Tauri CSP 策略已支持 style-src 'self' 'unsafe-inline'，内联样式可用
  • 所有新增 API 通过 Tauri invoke 调用，与现有架构一致
优先级建议：先实施 Phase 1 + Phase 2（不依赖后端改动），快速让用户感受到新界面的变化。Phase 3-4 需要后端配合，可并行开发。
